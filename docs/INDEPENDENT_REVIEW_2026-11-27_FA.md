# گزارش بازبینی مستقل و اصلاحات — ۲۷ نوامبر ۲۰۲۶

## دامنه و محدودیت ممیزی

این بازبینی روی بسته ZIP تحویلی `adine-vaccination-timing-caa3d6e` انجام شد؛ فایل ZIP فاقد تاریخچه Git و SHA مخزن است، بنابراین این گزارش تأییدکننده وضعیت PR یا آخرین commit در GitHub نیست. ۱۵۲ فایل در بسته وجود داشت که شامل ۷۷ فایل TypeScript/TSX، ۲۶ فایل تست و ۱۷ migration پایگاه داده است.

هیچ migration روی Supabase اجرا نشد، هیچ داده‌ای در پروژه ابری تغییر نکرد، هیچ PR تأیید/ادغام نشد و هیچ deploy انجام نشد.

## اصلاحات اعمال‌شده در این نسخه

1. **بازیابی زمان نمونه‌گیری:** تحلیل ذخیره‌شده اکنون زمان نمونه‌گیری را همراه با timestamp ISO، نام منطقه زمانی و offset ذخیره می‌کند. هنگام بازیابی، تاریخ و ساعت از همان لحظه زمانی بازسازی می‌شوند؛ بنابراین زمان تحلیل قبلی با تاریخ/ساعت جاری فرم اشتباه نمی‌شود.
2. **شفاف‌سازی زمان‌بندی:** عنوان کارت از عبارت توصیه‌محور به «برآورد زمانی رسیدن تیتر به BTT» تغییر کرد. توضیح افزوده شد که نمایش ساعت/دقیقه، دقت عددی محاسبه است نه دقت زیستی در حد دقیقه.
3. **MDA و provenance مستقل:** منبع، نسخه/صفحه و نوع منبع نیمه‌عمر از منبع، نسخه/صفحه و نوع منبع threshold جدا شدند. OD، S/P، S/N، درصد و index برای مدل افت نمایی تیتر پذیرفته نمی‌شوند؛ ورودی باید تیتر مثبت ratio-scale باشد.
4. **جلوگیری از ذخیره نتیجه MDA ناسازگار:** با تغییر تیترها، سن نمونه، نیمه‌عمر، threshold، واحد، منبع یا گله، خروجی قبلی نامعتبر می‌شود. ذخیره فقط وقتی ممکن است که خروجی متعلق به snapshot فعلی ورودی‌ها باشد.
5. **آستانه MDA:** برابری تیتر بازسازی‌شده روز هچ با threshold به‌عنوان رسیدن به آستانه در نظر گرفته می‌شود. اگر سن عبور محاسبه‌شده در گذشته یا در سن نمونه‌گیری باشد، هشدار صریح صادر می‌شود.
6. **ورود فایل Reader:** تشخیص ردیف‌های متداول کنترل مانند `Positive Control 1`، `Negative Control 1`، `PC1` و `NC1` تقویت شد. با انتخاب فایل جدید، mapping و حدود QC قبلی پاک می‌شوند و داده/metadata فایل قبلی در فرم والد پاک می‌شود.
7. **بانک کیت‌ها:** نوع آزمون یا کد بیماری ناشناخته دیگر به‌صورت پیش‌فرض ELISA یا IBD تعبیر نمی‌شود؛ رکورد ناشناخته به وضعیت `local-validation-required` و نوع `UNKNOWN` می‌رود.
8. **HI در روند IBV:** مقدار انفرادی `HI-log2` باید endpoint صحیح و گسسته باشد؛ مقادیر اعشاری رد می‌شوند.
9. **امنیت CI:** مجوز `contents` در workflow ساخت به `read` کاهش یافت، مرحله commit/push خودکار lockfile حذف شد و نصب وابستگی در workflowهای ساخت و deploy به `npm ci` تغییر کرد.
10. **مقیاس آزمون IBD:** موتور Deventer فقط ELISA و تیتر محاسبه‌شده با فرمول/نرم‌افزار همان کیت را می‌پذیرد؛ OD و S/P خام و HI/VN در مسیر محاسبه مسدود می‌شوند. برای کیت‌های ناشناخته، مقیاس پیش‌فرض نمی‌شود.
11. **ترتیب عملیات آفلاین:** صف همگام‌سازی دیگر mutation قبلی را هنگام ویرایش/حذف رکورد pending حذف نمی‌کند؛ زنجیره create → update → delete با revision/base متوالی حفظ می‌شود تا سرور عملیات را به ترتیب اعمال کند.
12. **کف سن و اصلاح Deventer:** حداقل سن برچسب محصول به‌عنوان کف اجباری به محاسبه سن و زمان تقویمی اضافه شد؛ اصلاح غیرصفر فقط برای نمونه‌گیری ۰ تا ۴ روز پذیرفته می‌شود؛ شروع/مدت ایمنی برچسب از تاریخ واکسیناسیون جدا نمایش داده می‌شود.

## راستی‌آزمایی انجام‌شده

- کامپایل strict ماژول‌های مستقل محاسباتی IBD، MDA، Reader import، IBV، ND، AIV، sampling age، آمار سرولوژی، baseline، flock reference، assay matcher و registryها با TypeScript سراسری موفق بود.
- ۷۶ فایل TS/TSX از نظر syntax با TypeScript transpile شدند؛ خطای syntax گزارش نشد.
- فایل‌های JSON مربوط به package، lockfile و manifest قابل parse بودند؛ دو workflow YAML نیز parse شدند.
- آزمون‌های کامل Vitest و build در محیط این نشست هنوز اجرا نشده‌اند. تست‌های اضافه‌شده باید روی CI واقعی همین commit اجرا شوند.

**محدودیت مهم:** اجرای `npm ci` در محیط بررسی با خطای npm متوقف شد و `vitest` در دسترس نبود؛ بنابراین `npm test` و `npm run build` کامل در این نشست اجرا نشدند. وضعیت CI فقط پس از اجرای GitHub Actions روی SHA نهایی قابل اعلام است. هیچ CI قدیمی به‌عنوان تأیید این commit استفاده نمی‌شود.

## وضعیت علمی مدل‌ها

- **IBD:** تنها موتور زمان‌بندی موجود، برآوردگر Deventer-style برای واکسن زنده متعارف است؛ محاسبه تنها وقتی قابل بررسی است که محصول مستند، BTT، assay متناظر، نیمه‌عمر، اصلاح سن، حجم نمونه و QC ثبت شده باشند. حتی در این حالت خروجی، پیش‌بینی حفاظت یا دستور قطعی واکسیناسیون نیست.
- **ND:** پایش توصیفی HI و پاسخ paired با شناسه پرنده وجود دارد؛ موتور مستقل زمان‌بندی MDA یا پیش‌بینی حفاظت وجود ندارد.
- **IBV:** پایش روند assay-specific وجود دارد؛ مدل زمان‌بندی MDA، حفاظت مخاطی یا cross-protection وجود ندارد.
- **AIV:** ماژول triage شواهد/ارجاع وجود دارد؛ مدل زمان‌بندی واکسن، تشخیص خودکار، DIVA مستقل یا پیش‌بینی حفاظت وجود ندارد.
- **MDA:** مدل افت نمایی اکتشافی است. تکمیل provenance به معنی تأیید منبع یا اعتبارسنجی زیستی نیست. نیمه‌عمر و threshold باید برای آنتی‌ژن، آزمون، جمعیت و هدف یکسان/مرتبط باشند.

## موانع باقی‌مانده پیش از انتشار

1. اجرای کامل `npm ci`، کل مجموعه Vitest و build روی CI واقعی همان SHA.
2. اجرای integration test واقعی RLS، sync چنددستگاهی، تعارض، tombstone و بازیابی پس از قطع اتصال روی پروژه Supabase هدف؛ این بازبینی صرفاً migrationها و کد را ایستا مرور کرده است.
3. تکمیل parserهای واقعی و نسخه‌دار برای فایل‌های خروجی BioChek/IDEXX/IDvet؛ fixtureهای موجود synthetic هستند و ورودی فعلی CSV/TSV متنی است. آرشیو خام در این نسخه در IndexedDB محلی ذخیره می‌شود؛ مسیر انتقال امن آن به جدول `reader_import_archives` در کد کلاینت تکمیل نشده است.
4. اعتبارسنجی مستقل آزمایشگاهی QC، تکرارپذیری، خطی‌بودن، محدوده اندازه‌گیری، LOD/ULOQ و تبدیل‌های هر کیت.
5. اعتبارسنجی آینده‌نگر و بیرونی در گله‌های تجاری ایران؛ تطبیق زمان برآوردی با پاسخ واکسن، شواهد بورس/مولکولی و پیامدهای بالینی.
6. تدوین مدل‌های اختصاصی و شواهددار برای ND، IBV و AIV؛ فرمول IBD یا نیمه‌عمر IBD نباید به بیماری‌های دیگر تعمیم داده شود.

## نتیجه

این ZIP یک نسخه **اصلاح‌شده برای ادامه آزمون و بازبینی** است، نه نسخه آماده استفاده بالینی یا انتشار عمومی. اصلاحات بالا اعمال شده‌اند، اما تا اجرای CI واقعی، build، آزمون‌های یکپارچه Supabase و اعتبارسنجی میدانی، وضعیت انتشار باید بسته بماند.
