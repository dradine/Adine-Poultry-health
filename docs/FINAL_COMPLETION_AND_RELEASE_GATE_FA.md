# گزارش وضعیت و معیار «تکمیل برنامه»

## قابلیت‌های موجود در شاخه MVP
- برنامه React/Vite، رابط فارسی RTL و ذخیره‌سازی محلی مرورگر.
- ثبت/انتخاب/حذف گله و ذخیره حداکثر ۱۰۰ تحلیل اخیر.
- محاسبه Deventer-style برای IBD متعارف زنده، آمار سرولوژی، تفسیر دو سطح و سناریوهای حساسیت.
- دروازه تأیید QC و ثبت منبع BTT/نیمه‌عمر/اصلاح.
- خروجی و بازیابی JSON با ادغام و محافظت از سوابق قبلی.
- تست‌های unit برای موتور، تفسیر، پشتیبان و رجیستری بیماری.
- رجیستری صریح وضعیت مدل‌ها: IBD آزمایشی؛ ND و IB پژوهشی/بدون موتور؛ AIV پیاده‌سازی نشده.

## تعریف تکمیل فنی
«تکمیل فنی» زمانی پذیرفته می‌شود که:
1. CI روی commit نهایی موفق باشد (TypeScript build + تست Vitest).
2. تست دستی iOS Safari و Android Chrome و مرورگر دسکتاپ انجام و نتیجه ثبت شود.
3. export/import، بازیابی بعد از refresh/بستن مرورگر، و حالت خطای فضای ذخیره‌سازی بررسی شود.
4. خروجی build و مسیر میزبانی واقعی بررسی شود.

## محدودیت اجرای آزمون در این محیط
- CI و تست خودکار از GitHub Actions قابل اجرا هستند.
- دسترسی مستقیم به دستگاه فیزیکی iOS/Android، Safari واقعی، داده‌های آزمایشگاه و محیط میزبانی تولید از این محیط وجود ندارد؛ بنابراین این موارد نباید «تست‌شده» یا «قبول نهایی» اعلام شوند.
- تست‌های واحد، اثبات‌کننده اعتبار علمی یا کارکرد آفلاین در همه دستگاه‌ها نیستند.
- برنامه فعلاً backend/auth/sync ندارد؛ داده‌ها در همان مرورگر/دستگاه می‌مانند. پاک‌کردن Site Data می‌تواند داده‌ها را حذف کند؛ backup ضروری است.

## معیار انتشار علمی
- مدل IBD باید با IFU دقیق کیت و واکسن، داده‌های واقعی و بازبینی مستقل اعتبارسنجی شود.
- مدل برای immune-complex و HVT-VP2 تعمیم داده نمی‌شود.
- ND، IB و AIV بدون مدل اختصاصی خروجی نمی‌دهند.
- نسخه فعلی یک تصمیم‌یار پژوهشی/آموزشی است، نه نسخه بالینی تأییدشده.
