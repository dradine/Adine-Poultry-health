# راهنمای آزمون دستی MVP زمان‌بندی واکسن IBD

این چک‌لیست برای آزمون نسخه شاخه `feature/ibd-first-mvp` است؛ آزمون دستی جای CI یا اعتبارسنجی علمی/میدانی را نمی‌گیرد.

## ۰) آزمون Wizard و کیت‌ها
- [ ] مرحله ۱ اطلاعات اولیه را می‌گیرد؛ نام گله و تاریخ برای ادامه ضروری هستند.
- [ ] مرحله ۲ بیماری را انتخاب می‌کند و دکمه‌های مرحله با پیش‌نیازها کار می‌کنند.
- [ ] مرحله ۳ کاتالوگ بیماری را فیلتر می‌کند؛ انتخاب کیت به مرحله ۴ منتقل می‌شود.
- [ ] آکاردئون افزودن کیت دستی فقط پس از بازشدن فرم را نشان می‌دهد و ثبت در مرورگر باقی می‌ماند.
- [ ] مدیریت کیت دستی، حذف رکورد را انجام می‌دهد.
- [ ] برای IBD کیت دستی محاسبه را باز نمی‌کند؛ کیت مستند و تطابق BTT/واحد لازم است.
- [ ] ND با کیت ELISA در موتور HI مسدود می‌شود؛ ND HI log2 به‌صورت درست تحلیل می‌شود.
- [ ] IBV، واحد انتخابی و روش کیت را ناسازگار تشخیص می‌دهد.

## ۱) ورود و ذخیره محلی
- [ ] برنامه بدون ورود حساب و بدون شبکه باز می‌شود.
- [ ] نام گله و تاریخ جوجه‌ریزی ثبت و پس از Refresh باقی می‌ماند.
- [ ] تحلیل معتبر ذخیره می‌شود و در فهرست سوابق دیده می‌شود.
- [ ] یک سابقه انتخاب و پارامترهای آن به فرم بازگردانده می‌شود.
- [ ] حذف گله و تحلیل، فقط همان مورد را حذف می‌کند.

## ۲) ورودی و کنترل علمی
- [ ] ورود تیتر با ارقام فارسی و انگلیسی و جداکننده‌های فاصله/ویرگول.
- [ ] تیتر ناقص، صفر، منفی، NaN، Infinity یا مقدار خارج از محدوده محاسبات را رد می‌کند.
- [ ] n=5 با کیت/واکسن مستند محاسبه اکتشافی و هشدار شدید حجم نمونه تولید می‌کند؛ n=1 محاسبه را متوقف می‌کند.
- [ ] بدون نام کیت/واکسن، منبع BTT، منبع نیمه‌عمر و منبع اصلاح، یا بدون هر سه تأیید QC، خروجی تولید نمی‌شود.
- [ ] اصلاح روز ۰ تا ۴ فقط برای نمونه‌گیری در همان بازه پذیرفته می‌شود.
- [ ] حالت «آستانه قبلاً رسیده» تاریخ آینده نشان نمی‌دهد.
- [ ] سناریوهای حساسیت ۵/۲۵/۷۵/۹۰ درصد نمایش داده می‌شوند.

## ۳) پشتیبان و بازیابی
- [ ] JSON پشتیبان دانلود و ساختار آن بازبینی می‌شود.
- [ ] واردکردن پشتیبان، رکوردهای تکراری را با ID ادغام می‌کند.
- [ ] رکورد بدون ID یا فایل با schema/version نامعتبر رد می‌شود.
- [ ] فایل خراب یا شکست ذخیره‌سازی، داده‌های قبلی را دست‌نخورده نگه می‌دارد.
- [ ] بازیابی در مرورگر/دستگاه دوم با داده نمونه انجام می‌شود.

## ۴) آزمون دستگاه واقعی
- [ ] iOS Safari: بازکردن، Refresh، ذخیره، بازیابی و دانلود JSON.
- [ ] Android Chrome: همان سناریوها.
- [ ] دسکتاپ Chrome/Firefox: همان سناریوها.
- [ ] بستن کامل مرورگر و بازگشایی، داده محلی را حفظ می‌کند.
- [ ] پاک‌کردن Site Data عمداً داده محلی را حذف می‌کند؛ قبل از آن پشتیبان گرفته شده است.

## معیار انتشار
- CI شامل TypeScript build و تست‌های Vitest باید سبز باشد.
- آزمون‌های دستی بالا در حداقل iOS و Android ثبت شوند.
- پیش از استفاده عملی: اعتبارسنجی مستقل پارامترها با کیت/واکسن واقعی و داده چند آزمایشگاه، بازبینی متخصص و تأیید دامپزشک مسئول ضروری است.
- این MVP فعلاً مدل IBD متعارف زنده است؛ برای immune-complex/HVT-VP2 یا ND/IB/AI خروجی تولید نمی‌کند.
- تا تکمیل اعتبارسنجی و تصمیم صاحب پروژه، PR در حالت Draft و branch مستقل بماند؛ ادغام در main یا انتشار عمومی خودکار انجام نشود.
