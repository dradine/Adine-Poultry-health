# وضعیت پیاده‌سازی Local-first و اتصال Supabase

تاریخ: ۱۴۰۵/۰۸/۲۵ — ۱۶ نوامبر ۲۰۲۶  
شاخه: `feature/ibd-first-mvp`  
مقصد PR: `main` — PR همچنان Draft و ادغام‌نشده است.

## آنچه اکنون پیاده‌سازی شده است

### ۱. ذخیره‌سازی محلی

- پایگاه داده IndexedDB با object storeهای `flocks`، `modelRuns`، `outbox` و `meta`.
- ثبت گله و تحلیل IBD در ذخیره‌سازی محلی؛ localStorage قدیمی برای سازگاری و نمایش رابط حفظ شده است.
- ثبت خروجی‌های ND، IBV و AIV در سوابق گله.
- عملیات ثبت و ایجاد outbox در یک تراکنش IndexedDB انجام می‌شود.
- حذف به‌صورت tombstone محلی ثبت می‌شود تا حذف آفلاین پس از اتصال همگام شود.
- تغییرات صف‌شده پس از خطای شبکه حذف نمی‌شوند؛ تعداد تلاش و آخرین خطا نگهداری می‌شود.

### ۲. احراز هویت و اتصال ابری

- Supabase JS با publishable key و URL پروژه پیکربندی شده است؛ هیچ service-role یا secret key در مرورگر قرار ندارد.
- ورود ایمیل/گذرواژه، ثبت‌نام، بازیابی و تغییر گذرواژه پیاده‌سازی شده است.
- نشست با SDK نگهداری و refresh token خودکار فعال است.
- همگام‌سازی فقط پس از ورود کاربر و برقراری اینترنت اجرا می‌شود.
- هنگام ارسال، `owner_id` از شناسه کاربر احراز‌شده گرفته می‌شود؛ از داده ارسالی کاربر به‌عنوان هویت استفاده نمی‌شود.
- جدول‌های عملیاتی `flocks` و `model_runs` ارسال و دریافت می‌شوند؛ داده‌های پایش ND/IBV/AIV نیز به `model_runs` متصل می‌شوند.

### ۳. سیاست تعارض و حفاظت داده

- شناسه محلی پایدار برای عملیات upsert استفاده می‌شود تا retry تا حد ممکن idempotent باشد.
- اجرای مدل‌ها append-only است؛ در retry اگر رکورد موجود باشد، دوباره بازنویسی نمی‌شود.
- برای ویرایش گله، `updated_at` نسخه محلی با نسخه ابری مقایسه می‌شود؛ نسخه قدیمی‌تر اجازه بازنویسی نسخه جدیدتر را ندارد.
- حذف گله در صورت وجود سوابق ابری بیشتر از سوابق محلی متوقف می‌شود تا حذف cascade داده‌ای که این دستگاه ندیده است رخ ندهد.
- پس از اتصال داده محلی به یک حساب، انتقال صف آن به حساب دیگر مسدود می‌شود.
- اگر دستگاه آفلاین باشد، داده در IndexedDB باقی می‌ماند و با رویداد online، تغییر داده یا بازگشت برنامه به حالت فعال دوباره تلاش می‌شود.

### ۴. سازگاری با نسخه قبلی و پشتیبان

- سوابق قدیمی localStorage به IndexedDB منتقل می‌شوند؛ مهاجرت بر اساس ID تکرارپذیر است.
- پشتیبان JSON علاوه بر داده‌های قبلی، snapshot گله‌ها و همه اجرای مدل‌ها را هم شامل می‌شود.
- بازیابی فایل پشتیبان، شناسه‌ها را merge می‌کند، رکوردهای تکراری را دوباره وارد نمی‌کند و رکوردهای جدید را در outbox قرار می‌دهد.
- snapshot قبل از ورود اعتبارسنجی می‌شود و ورود داده‌های نامعتبر/تحلیل بدون گله رد می‌شود.
- ورود snapshot جدید به IndexedDB در یک تراکنش انجام می‌شود.

### ۵. امنیت Supabase

- هر هفت جدول RLS فعال دارند.
- مجوزهای Data API محدود شده‌اند: کاتالوگ‌های مرجع `diseases`، `assay_kits` و `vaccine_products` فقط SELECT برای anon و authenticated دارند؛ جداول عملیاتی فقط برای authenticated و طبق RLS قابل دسترسی‌اند.
- نقش anon هیچ مجوزی برای خواندن/نوشتن گله، نتایج آزمایش یا اجرای مدل ندارد؛ فقط بانک مرجع غیرحساس را می‌خواند.
- سیاست‌های RLS مالکیت کاربر و ارتباط child-parent را کنترل می‌کنند.
- Security Advisor در آخرین بررسی finding نداشت.
- Smoke test واقعی CI به Auth endpoint وصل می‌شود و دسترسی anonymous به جدول diseases را بررسی می‌کند؛ این تست موفق است.

## بانک مرجع واکسن و کیت

- کاتالوگ‌های مرجع از Supabase بدون ورود قابل خواندن و در localStorage cache می‌شوند تا در بازدید بعدی آفلاین هم در دسترس باشند.
- انتخاب محصول Avishield IBD Plus به‌صورت خودکار BTT=500 واحد IDEXX و کیت متصل IDEXX IBD Ab Test، کاتالوگ 99-09260 را انتخاب می‌کند.
- رکورد محصول مربوط به برچسب GB، June 2024 است؛ در رابط صریحاً اعلام می‌شود که این رکورد مجوز عرضه در ایران نیست.
- کیت‌های غیرمستند در رجیستری، قفل محاسبه دارند؛ ورود دستی فقط با تکمیل provenance و تأیید تطبیق انجام می‌شود.
- BioChek CK113 به‌روزرسانی منبع RevB 2025 و راهنمای حداقل ۲۳ نمونه برای baseline/profile و پیش‌بینی زمان واکسیناسیون دریافت کرده است؛ این توصیه سازنده به همه کیت‌ها تعمیم داده نمی‌شود.

## مواردی که هنوز نیاز به تأیید/تکمیل دارند

1. **تأیید ایمیل:** تنظیم Auth پروژه تأیید ایمیل را الزامی می‌کند. SMTP و Redirect URL مجاز باید برای آدرس نهایی میزبانی بررسی شوند. تست ثبت‌نام واقعی با ایمیل کاربر انجام نشده است.
2. **میزبانی:** GitHub Pages در مخزن هنوز فعال نیست؛ workflow آزمایشی نتوانست Pages site را پیدا کند. workflow آن حذف شد تا CI بی‌دلیل قرمز نماند. برای میزبانی دائمی باید یک بار Pages در Settings فعال شود یا دامنه/میزبان اختصاصی متصل شود.
3. **آفلاین دستگاه واقعی:** رفتار IndexedDB و outbox تست واحد دارد، اما هنوز روی iOS Safari و Android Chrome با قطع اینترنت واقعی آزموده نشده است.
4. **رمزنگاری داده محلی:** داده‌های IndexedDB در سطح برنامه رمزنگاری اختصاصی نشده‌اند؛ امنیت دستگاه/مرورگر و قفل دستگاه اهمیت دارد.
5. **تعارض حل‌نشده:** در تعارض گله، سیستم جلوی overwrite را می‌گیرد و عملیات را در صف نگه می‌دارد؛ UI حل تعارض و انتخاب نسخه هنوز لازم است.
6. **همگام‌سازی آزمایشگاه:** جدول‌های `serology_batches` و `serology_results` در schema آماده‌اند، اما UI ورود/ parser آزمایشگاه و sync آن‌ها هنوز پیاده‌سازی نشده است.
7. **مدل علمی:** موتورهای ND/IBV/AIV پایش توصیفی‌اند؛ مدل MDA و زمان‌بندی مستقل برای این بیماری‌ها، مدل وکتورها، shedding/protection و اعتبارسنجی میدانی هنوز کارهای پژوهشی بعدی هستند.
